Part 1 · 先搞懂它

GitHub 到底是什么？

一句话：GitHub 是全球程序员放代码、管代码、一起写代码的平台，堪称"程序员的社交网络 + 云端仓库"。上面托管着超过 4 亿个项目，包括很多你每天都在用的软件。

📦 Git

一个工具软件（先有它）

  • 装在你自己电脑上的版本管理工具
  • 像游戏存档：每改一版代码都能"存个档"，随时读回任何一版
  • 不联网也能用，全在你本地
  • 由 Linux 之父 Linus 在 2005 年创造
VS

🌐 GitHub

一个网站平台（后诞生）

  • 把这些"本地存档"上传到云端，换个电脑也不怕丢
  • 像"代码界的网盘 + 朋友圈"：能看别人的项目、点Star收藏
  • 核心价值是多人协作：几十人改同一个项目也不会乱
  • 2018 年被微软收购，全球超过 1 亿开发者在使用
💡 小白只需记住：Git 是"工具"，GitHub 是"存放和分享成果的网站"。很多人混着说，其实你完全可以先只用 GitHub 网站（网页上点点鼠标就能玩转），以后再学 Git 命令也不迟——本教程就是这么安排的。
Part 2 · 核心概念

10 个必懂概念，全部用比喻讲明白

这些词你会在 GitHub 的每个角落看到。先混个眼熟，不用背，用到时回来查就行。

📁

仓库 Repository / Repo

比喻：一个项目的"专属文件夹"

一个仓库 = 一个项目的全部家当：代码、文档、修改历史都装在里面。可以是公开的（全世界的眼睛都能看），也可以是私有的（只有你自己和受邀的人能看）。

💾

提交 Commit

比喻：游戏里的"存一次档"

每完成一小步改动，就做一次 Commit，并写一句说明（比如"修好了登录报错"）。它像快照一样被永久记录，以后随时能回到任何一次存档的状态，再也不怕"改崩了回不去"。

🌿

分支 Branch

比喻：平行世界 / 草稿纸

默认主线叫 main。想大胆尝试新功能又怕搞坏主线？开一个分支（如 feature-login），在"平行世界"里随便折腾，稳了再合回去。就像写作业先打草稿，满意再誊到正式本上。

🔀

拉取请求 Pull Request / PR

比喻：交作业请老师批改，通过后并入正本

你在分支上改完，就发起一个 PR："我改了这些，请审核，没问题就合并进主线吧。" 项目维护者会逐行看你的改动、提意见，这是开源世界合作的核心方式。

🍴

复刻 Fork

比喻：把别人的菜谱完整抄一份到自己家

Fork 会把别人的仓库原样复制一份到你的账号下，你可以随便改而不影响原项目。改好了想"回馈原版"，就通过 PR 提交回去——这就是给开源项目贡献代码的路径。

⬇️

克隆 Clone

比喻：把云端文件夹整个下载到电脑

Clone 是把 GitHub 上的仓库完整下载到本地（包含全部修改历史）。下载后你可以离线编辑，改完再"推（push）"回 GitHub 同步。小白阶段用网页版可以暂时不碰它。

⭐

星标 Star

比喻：点赞 + 收藏夹二合一

觉得某个项目不错就点 Star：既是"赞"，也会把它收进你的 Star 列表方便以后找。Star 数是项目人气的直观体现，你也会经常看到"给个 Star 再走吧"。

🐛

议题 Issue

比喻：项目的"留言板 + 待办清单"

发现软件有 Bug？想提新功能建议？就在仓库里开一个 Issue。它也是开发团队的任务管理板：每个问题一个编号（#123），解决后关闭。不会写代码也能在这里帮上忙。

📖

自述文件 README

比喻：项目大门口的"说明书 / 招牌"

打开任何仓库首先看到的就是 README，它介绍这个项目是什么、怎么安装使用。写好 README 是新手的第一个练手任务——它用 Markdown 语法书写，比 Word 简单得多。

🤝

合并 Merge

比喻：把草稿誊写进正式版本

PR 审核通过后，分支上的改动就"合并"进主分支，成为正式版本的一部分。如果两拨人改了同一处产生冲突（Conflict），GitHub 会提示你手动选择保留哪边。

Part 4 · 手把手教程

8 步上手：今天就能拥有第一个仓库

前 7 步只用浏览器，不需要装任何软件、不需要会写代码。跟着做，约 20 分钟完成。

1

注册账号 Sign up

打开 github.com，点右上角 Sign up，依次填：邮箱 → 设置密码 → 起用户名 → 邮箱验证码。

  1. 用户名会出现在你的个人网址里（github.com/用户名），建议用英文小写+数字，好记且正式
  2. 选择 Free（免费）套餐即可，个人使用完全够
  3. 记得去邮箱点验证链接完成验证
✅ 小贴士：用户名起好后不要频繁更换，别人收藏的你的仓库链接会跟着变。
2

认一眼首页 Dashboard

登录后看到的就是控制台。现在只需要认识三个地方：

  1. 左上角 新建仓库按钮（New）—— 第 3 步要用
  2. 左侧栏 Repositories —— 你所有的仓库列表
  3. 右上角 头像 —— 进个人主页、设置 Settings
💡 页面是英文？点头像 → Settings → 最底部可能找到语言设置，或者装个浏览器翻译插件。不过建议趁早熟悉英文界面，因为所有教程截图都是英文的。
3

创建第一个仓库 New Repository

点 New 按钮，按下面填：

  1. Repository name：填 hello-github
  2. Description（可选）：写"我的第一个 GitHub 仓库"
  3. 选 Public（公开，能被别人看到）或 Private（私有）
  4. ✅ 勾选 Add a README file（它会自动生成门面说明书）
  5. 点绿色按钮 Create repository —— 恭喜，仓库诞生！🎉
⚠️ 仓库名创建后可以改，但链接会变，所以第一次尽量想好再填。
4

上传一个文件并完成首次提交 Upload & Commit

进仓库后点 Add file → Upload files，随便拖一个文件进去（图片、txt 都行），然后：

  1. 在 Commit changes 的第一个输入框写提交说明，如 上传我的第一张图片
  2. 点绿色 Commit changes 按钮

这就是一次完整的"存档"。文件列表里现在能看到它了。

✅ 提交说明（commit message）写清楚"做了什么"，是程序员的基本修养，从头养成好习惯。
5

编辑 README，学会 Markdown Edit README

点开 README.md → 右上角铅笔图标 ✏️ 进入编辑，试着写：

README.md（Markdown 语法）
# 一级标题（这是最大的标题）
## 二级标题

普通文字直接写，**加粗**用两个星号，*斜体*用一个星号。

- 减号加空格 = 列表
- 列表第二行

[点我去看GitHub](https://github.com) ← 中括号是文字，圆括号是链接

点 Preview 标签可实时预览效果，最后 Commit 保存。Markdown 是写文档的通用语言，5 分钟就能上手。

6

体验分支与 PR（理解协作流程）Branch & Pull Request

用自己的仓库也能演练一遍专业协作流程：

  1. 仓库页左上方分支下拉框里输入 my-first-branch → 点 Create branch
  2. 在新分支上随便改点东西（比如往 README 加一行），Commit
  3. 点 Compare & pull request，写两句话说明，点 Create pull request
  4. 检查改动没冲突后，点 Merge pull request → Confirm merge
  5. 切回 main 分支——你的改动已经"转正"了！
💡 这个"开分支 → 改动 → PR 审核 → 合并"的流程，就是全世界程序员协作开发的标准姿势，你现在已经在真实仓库里走完了它。
7

给别人的项目点 Star & 提 Issue Star & Issue

去 github.com/trending 逛逛热门项目：

  1. 找到感兴趣的项目点 ⭐ Star 收藏（以后在头像 → Your stars 里找）
  2. 点进 Issues 标签，看看大家在讨论什么、提了什么问题
  3. 如果发现 Bug 或有疑问，点 New issue 也提一个——这就是参与开源的第一步
✅ Star 和 Issue 完全不需要会写代码，今天就能参与。
8

（选修）把项目下载到电脑上 Git & Clone

当你需要在本地写代码时，再学这一步：安装 Git（git-scm.com）或图形化工具 GitHub Desktop，然后克隆仓库：

命令行 · 最常用的 6 条 Git 命令
git clone https://github.com/用户名/hello-github.git  # 把云端仓库下载到本地
git status                        # 看看当前改了什么
git add .                        # 把改动放进"待存档清单"
git commit -m "写清楚这次改了啥"   # 存档（本地）
git push                          # 把存档推送到 GitHub 云端
git pull                          # 把云端最新版本拉回本地
⚠️ 不着急！纯网页操作已经能完成 80% 的新手需求，这步可以等你真正需要本地写代码时再学。

Part 6 · 疑难解答

新手最常见的 7 个问题

GitHub 是免费的吗？公开我的代码安全吗？
免费套餐已包含不限量的公开和私有仓库，个人使用绰绰有余。担心安全就建 Private 私有仓库，只有你能看。另外注意：永远不要把密码、API 密钥等敏感信息传到公开仓库。
我不会编程，GitHub 对我有用吗？
有用！GitHub 本质是"带版本历史的云端文件库 + 协作平台"：写论文、记笔记、管文档、放作品集都可以。GitHub Pages 还能免费建个人网站。把仓库当"会存档的网盘"来用，完全没问题。
GitHub 和 Gitee（码云）是什么关系？
Gitee 是国内公司做的类似产品，功能和 GitHub 类似，国内访问速度快。但 GitHub 是全球最大的开发者社区，开源项目几乎都在上面。学概念一通百通，会 GitHub 就会用一切同类平台。
国内访问 GitHub 慢/打不开怎么办？
常见解决思路：① 高峰期多刷新或换个时间段；② 只是下载代码的话，可以用镜像加速站；③ 浏览器装 GitHub 加速类扩展；④ 用 GitHub Desktop 客户端有时比网页稳定。具体方法时效性强，搜索"GitHub 加速"找最新方案。
我不小心删错/改错了东西怎么办？
这正是 GitHub 的价值——几乎一切都有历史记录。仓库里点 Commits 能看到每次存档，可以查看任意历史版本。文件被删了？在提交历史里能找回。所以放心大胆地折腾。
Fork、Clone、Download ZIP 有什么区别？
Fork：复制到"你的 GitHub 账号"下，为参与协作做准备；Clone：下载到"你的电脑"，且和 GitHub 保持双向同步关系；Download ZIP：单纯打包下载一份，不保留历史、无任何后续关联，只想看看代码时用它。
学完这个网站，下一步该学什么？
推荐路线：① 练熟 Markdown 写文档 → ② 学 Git 命令行（或先玩 GitHub Desktop 图形界面）→ ③ Fork 一个感兴趣的小项目并提交第一个 PR → ④ 用 GitHub Pages 搭个人主页 → ⑤ 看实战 3 把一个工具站从想法做成上线（真实复盘） → ⑤ 学习 GitHub Actions 自动化。其中「搭个人网站」和「提交第一个 PR」本站已备好专题实战教程：Pages 建站实战 与 首个 PR 实战，其余可在下方资源里找到官方教程。
