主页/专题实战 2

🔀 提交你人生第一个 PR

给开源项目做贡献听起来遥不可及？其实你的名字可以今天就能写进一个项目的贡献者名单—— 而且全程只用浏览器，甚至不需要会写代码。

✅ 前置要求：已完成主页教程第 1~7 步（有账号、了解 Fork 和 PR 的概念）
💪 先做心理建设：PR ≠ 必须写高深代码。开源项目里最缺的往往是最基础的贡献——改错别字、修失效链接、补一句文档、翻译、加一张截图，都是正式贡献，都会让你的头像出现在项目的 Contributors（贡献者）名单里。全世界的程序员，几乎都是从"帮项目改了个 typo"开始的。
Step 1

找一个适合新手的下手对象

别一上来就挑战 Linux 内核。挑项目的三条路：

🏷️

搜 "good first issue" 标签

在 GitHub 搜索框输入 label:"good first issue"，或直接逛 github.com/topics/good-first-issue。这些议题是项目方专门留给新手的，难度有保障。

📖

从文档类仓库下手

找你熟悉的软件的中文文档 / 教程仓库（很多开源项目都有 docs 仓库），看到错别字、过期链接、翻译别扭的地方，就是你的机会。纯文字改动，几乎不会被拒绝。

🧭

先读贡献指南

像样的仓库根目录都有 CONTRIBUTING.md（如何参与贡献）和 README.md。动手前花五分钟读一遍，能避开 90% 的退回原因。

⚠️ 两条红线：不要一次提很多个雷同的 PR 刷存在感（会被当成 spam 拉黑）；不要抢别人已经在做的 Issue（先在 Issue 里留言问一句"这个我可以试试吗？"）。
Step 2

Fork 复制仓库，然后动手改

A

点 Fork，把项目复制到自己账号下

  1. 进入目标仓库，点右上角 Fork 按钮
  2. 弹窗里直接点 Create fork，几秒后 你的用户名/项目名 就出现在你账号下了
💡 Fork 之后页面顶部会有一行小提示："This branch is X commits behind 原作者:main"——这是正常的，说明这是你的副本。
B

在你自己的副本里编辑文件（网页端即可）

  1. 找到要改的文件，点右上角 ✏️ 铅笔图标 进入网页编辑器
  2. 做你的修改：改错别字、补文档、调翻译……一次只改一件事
  3. 点右上角绿色 Commit changes，在弹窗里：
    • 提交说明写清楚，如 docs: 修正第 3 章的"登陆"错别字为"登录"
    • 选择 Commit directly to the main branch（新手首次直接提交即可）
✅ 提交说明格式建议：类型: 做了什么，类型用 docs（文档）、fix（修复）、feat（新功能）。这是开源社区的通用习惯。
Step 3

发起 Pull Request

A

点 "Contribute → Open pull request"

  1. 回到你 Fork 的仓库首页，文件列表上方会出现一条横幅：This branch has changes that are proposed…，点 Contribute → Open pull request
  2. GitHub 会自动对比"原仓库 ← 你的副本"，确认底部显示 Able to merge（无冲突）
B

写好标题和描述（决定成败的一步）

维护者每天收到很多 PR，一篇清爽的描述能大大提高通过率。照这个模板写：

PR 描述模板（可直接套用）
## 改了什么
修正 README.md 第 42 行的错别字："登陆" → "登录"

## 为什么改
中文语境下"登录"是标准用法，全文其他地方也都用的"登录"

## 截图（如改动涉及页面显示）
（贴一张修改前后的对比图更好）
  1. 填好标题和描述，点 Create pull request
  2. 🎉 你的 PR 已经出现在原仓库的 Pull requests 标签页里，有专属编号（如 #128）
Step 4

等待审核、修改、被合并

PR 提交后进入维护者的审核队列。接下来发生的一切都在 PR 页面（Notification 通知 + 邮件）里进行。

✅ 直接合并 Merge

审核通过，你的改动进入原项目主线。你的头像会出现在仓库的 Contributors 名单里，个人主页也会新增一枚贡献徽章。

✏️ Request changes

维护者留言让你修改。别慌，这正是流程的一部分：回到你 Fork 的仓库，继续编辑文件并 Commit——新提交会自动出现在同一个 PR 里，无需重开。

💬 Comment 讨论

对方有疑问，在评论区礼貌回复即可。沟通语言看项目惯例（很多中文项目用中文）。

⏳ 没人理？

维护者都是用业余时间做开源，等一周很正常。可以在同一个 PR 下礼貌地留一句跟进："Hi，方便时帮忙看一下这个 PR 吗？谢谢！"

🏆 合并之后：去原仓库点 Insights → Contributors，找到你的头像截图留念吧。这就是你的第一份开源履历，写进简历都是加分的。
疑难解答

第一个 PR 常见问题

PR 被拒绝了怎么办？很丢人吗？
完全正常，任何人的 PR 都可能被拒。看一眼拒绝理由：方向不符合项目规划（学到了解项目）、改法不对（学到了正确姿势）、或者就是维护者没精力。礼貌回一句"感谢反馈，我学到了"，然后找下一个项目。没有人会记得被拒的 PR，但你的贡献者名单会一直都在。
PR 和我直接编辑别人仓库有什么区别？
你对别人的仓库没有直接写权限——点铅笔时 GitHub 会自动帮你 Fork 一份再改，改完必须通过 PR 请有权限的人审核合并。而自己的仓库自己就是管理员，所以主页教程第 6 步才能一键 Merge。
提交之后发现改错了，还能补救吗？
能。继续在你 Fork 的文件上修改并 Commit，新改动会自动同步进这个 PR（一个 PR = 一个分支上的所有提交）。整个 PR 不要了就点 Close pull request 关掉即可，随时可以重新开。
我的 Fork 落后原项目很多了，怎么同步？
在你 Fork 的仓库页点 Sync fork → Update branch，一键把原项目的最新内容拉下来。建议每次动手贡献前先做这一步，减少冲突。
有没有专门给新手练手的官方途径？
有：① firstcontributions 项目（搜 "first-contributions"）——专门让新手在一个教学仓库里完成第一个 PR 的互动教程；② GitHub 官方的 GitHub Skills（skills.github.com）也有 PR 实战课。建议先在这里"试刀"，再去真实项目贡献。
